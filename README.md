# Binance Price Service

REST-сервис на Spring Boot 3 и Java 21, который по расписанию опрашивает API биржи Binance, сохраняет среднюю цену торговой пары (`BNBUSDT`) в PostgreSQL и предоставляет API для выборки котировок, вычисления средней цены за период и анализа тренда.

---

## Стек технологий

* **Язык:** Java 21 (LTS)
* **Фреймворк:** Spring Boot 3.5 (Spring Web, Spring Data JPA, Validation)
* **База данных:** PostgreSQL 17
* **Миграции:** Flyway
* **Документация:** Springdoc OpenAPI 2.10 (OpenAPI 3.1, Swagger UI)
* **Тестирование:** JUnit 5, Mockito, AssertJ, WireMock, Testcontainers (PostgreSQL 17)
* **Контейнеризация:** Docker, Docker Compose
* **CI:** GitHub Actions (сборка и запуск тестов при push)

---

## Запуск приложения

### Способ 1: Через Docker Compose

1. *(Опционально)* Создайте файл `.env`, если хотите изменить стандартные порты или параметры подключения (по умолчанию всё уже преднастроено и работает без создания файла):
   ```bash
   cp .env.example .env
   ```

2. Соберите и запустите контейнеры:
   ```bash
   docker compose up --build -d
   ```

3. Просмотр логов сервиса:
   ```bash
   docker compose logs -f app
   ```

4. Остановка контейнеров:
   ```bash
   docker compose down
   ```

---

### Способ 2: Локальный запуск без Docker

Если у вас уже запущен локальный сервер PostgreSQL:

1. Убедитесь, что база данных создана (таблицы и индексы Flyway создаст автоматически при старте):
   ```sql
   CREATE DATABASE prices_db;
   ```

2. Запустите сервис через Maven:
   ```bash
   mvn spring-boot:run
   ```

> По умолчанию сервис подключается к `localhost:5432/prices_db` с пользователем и паролем `postgres/postgres`.  
> Переменные из таблицы конфигурации можно выборочно переопределить через аргументы запуска — передавайте только то, что отличается от дефолта:
> ```bash
> # Пример выборочного переопределения (пароля и порта базы данных):
> mvn spring-boot:run -Dspring-boot.run.arguments="--POSTGRES_PASSWORD=secret --POSTGRES_PORT=5433"
> ```

## Конфигурация и переменные окружения

Конфигурация приложения управляется через переменные окружения:

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `BINANCE_BASE_URL` | Базовый URL API Binance | `https://api.binance.com` |
| `BINANCE_POLL_INTERVAL` | Интервал опроса биржи в формате ISO-8601 | `PT30S` |
| `BINANCE_SYMBOL` | Торговая пара для отслеживания | `BNBUSDT` |
| `APPLICATION_PORT` | Внешний порт приложения (в Docker) | `8080` |
| `POSTGRES_HOST` | Хост базы данных | `db` (в Docker) / `localhost` |
| `POSTGRES_PORT` | Порт базы данных | `5432` |
| `POSTGRES_DB` | Имя базы данных | `prices_db` |
| `POSTGRES_USER` | Пользователь БД | `postgres` |
| `POSTGRES_PASSWORD` | Пароль пользователя БД | `postgres` |
| `APP_LOG_LEVEL` | Уровень логирования приложения | `INFO` |

## REST API

После запуска приложения интерактивная документация и песочница доступны по адресу:
* **Swagger UI:** `http://localhost:8080/swagger-ui.html`
* **OpenAPI спецификация (JSON):** `http://localhost:8080/v3/api-docs`

---

### Эндпоинты

#### 1. Последняя актуальная цена
Возвращает самую свежую сохраненную котировку из базы данных.

* **HTTP-метод:** `GET /api/v1/prices/latest`
* **Параметры:** отсутствуют.
* **Пример вызова:**
  ```bash
  curl "http://localhost:8080/api/v1/prices/latest"
  ```
* **Пример ответа (200 OK):**
  ```json
  {
    "symbol": "BNBUSDT",
    "price": 699.06658204,
    "fetchedAt": "2026-11-03T15:23:19Z"
  }
  ```

---

#### 2. Средняя цена за период
Рассчитывает среднее арифметическое сохраненных цен за интервал `[from, to]` с округлением `HALF_UP`.

* **HTTP-метод:** `GET /api/v1/prices/average`
* **Параметры запроса:**
  * `from` *(обязательный)* — начало периода в формате ISO-8601 с точностью до секунд (UTC или со смещением, 1970–9999 гг.).
  * `to` *(обязательный)* — конец периода в формате ISO-8601 с точностью до секунд (не раньше `from`, UTC или со смещением, 1970–9999 гг.).
* **Пример вызова:**
  ```bash
  curl "http://localhost:8080/api/v1/prices/average?from=2026-11-01T00:00:00Z&to=2026-11-03T23:59:59Z"
  ```
* **Пример ответа (200 OK):**
  ```json
  {
    "averagePrice": 698.84510291
  }
  ```

---

#### 3. Список котировок с пагинацией
Возвращает список сохраненных цен в интервале `[from, to]` с сортировкой от новых к старым (`DESC`).

* **HTTP-метод:** `GET /api/v1/prices`
* **Параметры запроса:**
  * `from` *(обязательный)* — начало периода в формате ISO-8601 с точностью до секунд (UTC или со смещением, 1970–9999 гг.).
  * `to` *(обязательный)* — конец периода в формате ISO-8601 с точностью до секунд (не раньше `from`, UTC или со смещением, 1970–9999 гг.).
  * `page` *(обязательный)* — номер страницы, целое число `>= 0`.
  * `size` *(обязательный)* — количество записей на странице, целое число от `1` до `100`.
* **Пример вызова:**
  ```bash
  curl "http://localhost:8080/api/v1/prices?from=2026-11-01T00:00:00Z&to=2026-11-03T23:59:59Z&page=0&size=2"
  ```
* **Пример ответа (200 OK):**
  ```json
  {
    "items": [
      {
        "symbol": "BNBUSDT",
        "price": 699.06658204,
        "fetchedAt": "2026-11-03T15:23:19Z"
      },
      {
        "symbol": "BNBUSDT",
        "price": 699.08968942,
        "fetchedAt": "2026-11-03T15:22:48Z"
      }
    ],
    "page": 0,
    "size": 2,
    "totalElements": 535,
    "hasNext": true
  }
  ```

---

#### 4. Вычисление тренда цены
Анализирует динамику между первой и последней котировкой за выбранный диапазон времени.  
Возможные значения `trend`:
* `UPWARD` — цена выросла.
* `DOWNWARD` — цена упала.
* `FLAT` — цена не изменилась (или в интервале ровно одна запись).

* **HTTP-метод:** `GET /api/v1/prices/trend`
* **Параметры запроса:**
  * `from` *(обязательный)* — начало периода в формате ISO-8601 с точностью до секунд (UTC или со смещением, 1970–9999 гг.).
  * `to` *(обязательный)* — конец периода в формате ISO-8601 с точностью до секунд (не раньше `from`, UTC или со смещением, 1970–9999 гг.).
* **Пример вызова:**
  ```bash
  curl "http://localhost:8080/api/v1/prices/trend?from=2026-11-03T00:00:00Z&to=2026-11-03T23:59:59Z"
  ```
* **Пример ответа (200 OK):**
  ```json
  {
    "symbol": "BNBUSDT",
    "startDate": "2026-11-03T00:00:00Z",
    "endDate": "2026-11-03T23:59:59Z",
    "trend": "DOWNWARD"
  }
  ```

## Обработка ошибок

Ошибки валидации (отсутствие обязательных полей, некорректный формат ISO-8601, инвертированный диапазон `to < from`, выход за границы поддерживаемых дат, некорректные параметры пагинации) возвращают статус `400 Bad Request` в формате `application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "Validation failed",
  "instance": "/api/v1/prices/average",
  "errors": [
    "Parameter 'to' must not be before 'from'"
  ]
}
```

Для эндпоинтов `/latest`, `/average` и `/trend` при отсутствии данных возвращается `404 Not Found`:
```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "No prices found for symbol 'BNBUSDT' in range [2026-11-01T00:00:00Z, 2026-11-02T00:00:00Z]",
  "instance": "/api/v1/prices/average"
}
```

## Архитектурные решения

* **Точность финансовых расчетов:** Цены обрабатываются через `BigDecimal` и хранятся в типе `NUMERIC(18, 8)`. В конфигурации Jackson включен `write-bigdecimal-as-plain: true`, что предотвращает сериализацию чисел в экспоненциальную нотацию вида `6.99E2`.
* **Индексация и защита от дублирования:** Составной уникальный индекс `(symbol, fetched_at)` исключает повторные записи и идеально ложится на паттерн запросов сервиса (выборка по торговой паре за диапазон дат).
* **Версионирование схемы БД:** Структура таблиц и ограничений управляется через Flyway-миграции, а автогенерация схемы Hibernate (`ddl-auto`) переведена в строгий режим `validate`.
* **Управляемость шедуллера:** Планировщик вынесен в отдельную конфигурацию и управляется свойством `scheduler.enabled` через `@ConditionalOnBooleanProperty`, что позволяет изолировать и отключать фоновый опрос в интеграционных тестах.
* **Изолированное тестирование:** Интеграционные тесты выполняются в реальном PostgreSQL через Testcontainers с накатом Flyway-миграций, а сетевые вызовы к Binance изолированы с помощью WireMock.
* **Стандартизация ошибок:** Обработка исключений построена на базе `ProblemDetail` и `ResponseEntityExceptionHandler`, обеспечивая единообразный формат ответов об ошибках для всего REST API.
